<objective>
Give the operator the one-time `auth` command that creates the radar's own read-only Guard login (D-04): OAuth authorization code with PKCE against Fleet, dynamic client registration as a public client, the redirect address pasted into a hidden terminal prompt (never chat, argv or shell history), strict validation of everything that comes back, and the login stored in `<state-dir>/guard-auth.json` (mode 0600), where the token layer of plan 02-03 refreshes it unattended. The file is the place D-07 fixes for the rotating refresh token and the one exception AGENTS.md names to "secrets come from env / .env"; `auth` never reads or writes a Guard token in env or `.env`.

Purpose: SRC-01 needs a login that exists without Claude Code's session; the MVP's unattended week depends on getting a refresh token and refusing anything broader than read scopes.
Output: core `guard_login.py`, the login transport methods in `guard_credentials.py`, shell `cli_auth.py`, the `auth` subcommand in `cli.py`, fakes and tests. The real login is created by the operator on the production host in plan 02-11; no executor runs it against Fleet.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator browser -> pasted redirect address -> radar | The address carries a one-time code; it crosses a terminal, never chat |
| radar -> Fleet discovery, registration and token endpoints | Untrusted metadata and grants over TLS |
| radar -> state/guard-auth.json | Long-lived refresh token written once here |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-15 | Spoofing | authorization code interception or injection | high | mitigate | PKCE S256 with an 86-character verifier from secrets, random state compared with hmac.compare_digest, exact redirect URI match, code used once and dropped |
| T-02-16 | Spoofing | mix-up attack (code from another authorization server) | high | mitigate | Pinned issuer https://fleet.enji.ai checked in protected-resource and server metadata; iss in the redirect required and compared (RFC 9207, advertised by Fleet) |
| T-02-17 | Elevation of privilege | scope of the grant | high | mitigate | Registration and authorize request ask for projects:read audits:read only; credentials_from_grant refuses any scope outside them (audits:run included) and a grant without refresh token; nothing is stored then |
| T-02-18 | Information disclosure | pasted address, code, verifier, tokens | high | mitigate | getpass prompt (no echo, not argv, not env, not shell history); tokens stored only in guard-auth.json 0600 (D-07); authorize URL printed to stdout only, never logged; fixed LoginError reasons; secrecy rows grep stdout, stderr and caplog |
| T-02-19 | Tampering | discovered endpoints (SSRF or downgrade) | medium | mitigate | https-only endpoints, issuer equality, endpoints stored once in the credential file so unattended runs never re-discover |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed in this plan; `git diff --exit-code main -- uv.lock pyproject.toml` stays clean |
