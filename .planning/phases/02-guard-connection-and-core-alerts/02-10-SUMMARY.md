# 02-10 Summary: unattended run, timer, runbook

- `poll_cost.py` (core): `CountingGuardTools(inner, monotonic)` counts calls, failed calls (re-raised unchanged) and seconds per tool; `format_poll_cost` renders the one-line `poll cost: N calls (...), F failed, S s, P projects, R repositories`.
- `cli.py`: `run --fixtures` is optional; without it the source is `_LazyGuard`, which connects through the connector (default `open_guard(state_dir, clock=system_clock)`, never the `--now` clock) on the first call, so a run that finds the lock held or the state corrupt never connects. A connection failure is remembered and raised on every call, so it becomes a failed poll (health, saved state, ops chat). The session is closed in a `finally`. Every run logs the poll-cost line; a dry-run prints it as the last line after `summary:`. The credential store is never stubbed in a dry-run, so a rotated refresh token reaches `guard-auth.json`.
- `deploy/systemd/enji-guard-radar.service` (oneshot, `TimeoutStartSec=15min`, hardened, installed entry point, no secret), `.timer` (`00/3:00:00`, `Persistent=true`), `deploy/cron.example` (`timeout 15m`, no flock wrapper, comment says why), `docs/deploy.md` (runbook, 12 sections).
