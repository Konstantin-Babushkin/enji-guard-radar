# 02-08 Summary: doctor command

- `telegram.py`: `TelegramResult.result` (the API's result object, else None), `chat_payload_id` (shared with the notifier, behaviour unchanged) and `call_method(token, method, payload, transport)` for getMe, getChatMember and getChat. The URL stays in a local variable; the description is redacted before it is returned.
- `doctor.py` (core, pure): `CheckStatus`, `CheckResult`, `DoctorReport` (`exit_code`), plain fact types (`ApiAnswer`, `ApiUnreachable`, `CredentialFacts`, `GuardFacts`) and the verdicts for settings, config, state, unevaluated projects, credentials, getMe, getChatMember, getChat permissions and Guard, plus `timer_hint` and `format_doctor`. Details hold status words, ids, variable names and fixed texts only; Telegram descriptions are matched against ("chat not found") but never printed.
- `cli_doctor.py` (shell) and `cli.py`: the `doctor` subcommand (`--state-dir`, `--env-file`, `--config`) and `main(..., guard_connector=...)`, default `open_guard`. Fixed order: settings, config, state, unevaluated projects, credential file, getMe, group getChatMember, getChat (only when the bot is in the group), ops getChatMember, Guard, timer hint. A failed getMe skips the chat checks with "needs a valid bot token"; a missing credential file skips Guard without calling the connector. Nothing is sent and `state.json` is never written; the credential file is rewritten only when a refresh is due, through the real store and lock.
- Tests: `tests/test_doctor.py` (74 rows: tracer through `cli.main`, verdict tables, broken setups, refresh, secrecy, no send, no state write), `tests/test_telegram.py` (`call_method` rows), `cli_doctor` added to `SHELL_MODULES`.
- Gate: `make verify` -> `959 passed in 25.46s`.
- Decision: `cli_doctor` keeps its own small config reader instead of importing `cli.read_config` (import cycle).
- Known gap: plan 02-07 stamps `health.last_success_at` only when a failure streak ends, so the unevaluated-projects line is usually SKIP "no successful Guard poll yet" until a failure has happened.
- Human checkpoint: none in this plan. The doctor run on the production host is plan 02-11 and is left to the operator.
