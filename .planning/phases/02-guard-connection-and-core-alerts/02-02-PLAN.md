## Defaults and settled questions

- Default M = 2 (`high.clear_after_clean_runs`): RESOLVED in 02-RESEARCH.md Open Question 5 as a config default; the operator tunes it from real data in plan 02-11.
- Default `defaults.high_aged_after_days` = 14 (RESOLVED in 02-RESEARCH.md Open Question 5, tuned in plan 02-11), the same as the stale default; per-project overrides exist because RULE-10 requires them for every threshold.
- `high.audit_types: null` tracks every audit type with scored findings, not only `audit.security` and `audit.public-api-access-safety` (RESOLVED in 02-RESEARCH.md Open Question 3); the operator narrows it with a list. RULE-03's two security types are covered either way.
- Age alone never sends (ALERT-01; RESOLVED in 02-RESEARCH.md Open Question 2).
- Age origin is D-02 as amended on 2026-11-17 (RESOLVED in 02-RESEARCH.md Open Question 4): the age counts from the completed_at of the first High run the radar observed for the series (HighSeries.opened_at). The label is "Seen by the radar since <date>". That date is never later than the first poll and can be earlier. The accepted consequence is that a long-standing finding still looks young when the radar started late, and the "Seen by the radar" wording keeps that visible.
- "aged" is strictly "longer than" the threshold, as RULE-02 is worded (Phase 1's stale rule uses ">=", a known open point that this plan does not change).
