<objective>
Tell the operator when the radar itself stops working and when it recovers (OPS-02, D-03): every poll is classified as ok or failed with a cause (auth, unavailable, data), a pure state machine counts consecutive failures in the saved State, one ops message goes out after K failures, one recovery message after the first good poll, both marked only after the ops chat acknowledges. A failed Guard login is just another failed poll, worded so the operator knows to run `enji-guard-radar auth`.

Purpose: without the weekly digest (Phase 3) the ops chat is the only signal that a silent radar is broken; it must neither spam nor stay silent, and K must actually advance across timer runs.
Output: core `health.py`, cause plumbing in `guard.py`, `ops.failures_before_alert` in config, pipeline wiring with save-on-failure, and tests.
</objective>
