<objective>
Build the radar's own unattended Guard login layer (D-03, D-04): a credential file under `state/`, a refresh that persists rotated tokens before they are used, a pure classification of token-endpoint answers into "re-auth needed" and "just retry", and a lock so `run`, `doctor` and `probe` can never burn each other's refresh token. The interactive `auth` command (plan 02-05) and the MCP adapter (plan 02-06) build on these contracts.

Purpose: research found that the MCP SDK's own OAuth provider refreshes against the wrong URL in a fresh process and cannot tell `invalid_grant` from a 503; "unattended for 7 days" (MVP acceptance 2) depends on this layer.
Output: contracts in `ports.py`, core `guard_auth.py`, shell `guard_credentials.py`, an `atomic_write` helper extracted from `state_store.py`, a fake OAuth transport and tests.
</objective>

## Decisions recorded here

- Own token layer instead of the SDK's OAuthClientProvider (research Pitfall 1, verified by spike). Reversible: the transport consumes the `AccessTokenSource` protocol only.
- The refresh token lives in `state/guard-auth.json` (mode 0600, directory 0700, git-ignored), not in `.env` (Claude's discretion in CONTEXT.md: `.env` and systemd EnvironmentFile cannot be rewritten atomically on rotation). Reversible: running `auth` again recreates the file.
- ASSUMPTION A2: Guard rotates refresh tokens (RFC 9700); persist-before-use is harmless if it does not. ASSUMPTION A3: lifetimes unknown until the first real `auth` (plan 02-11).
- Registering `cli_auth` and `mcp_guard` in SHELL_MODULES here lets plans 02-05 and 02-06 run in parallel in wave 2 without both editing tests/test_architecture.py; listing a module that does not exist yet has no effect on the checks.

## Trust Boundaries

| Boundary | Description |
