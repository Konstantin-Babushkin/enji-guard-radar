## Notes

- A failed call (TriageFailed) counts in calls and failures; a reply that validation later rejects is a call, not a failure here (the failure count is about the call itself; rejection counts are logged by plan 04-08).
- Dry-run (D-14: logs the lines, writes no file): `triage_cost_store.py` also provides `ReadOnlyTriageCostStore(inner)`, modelled on the read-only state store wrapper in state_store.py: `load()` delegates, `save()` writes nothing and logs at DEBUG "dry-run: triage cost not written". Plan 04-13's CLI wiring uses it for `--dry-run`, so the daily line in a dry-run is today's file total plus the dry-run call, computed in memory.

## Failure behaviour

- Cost file read: missing -> empty; corrupt or unreadable -> one WARNING, treated as empty, overwritten on the next save. Never halts, never touches the state file.
- Cost file write: atomic; on OSError one WARNING with the error class, the run continues, exit code unchanged.
