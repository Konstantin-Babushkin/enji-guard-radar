## Notes

- If the system prompt cannot be passed by a flag (notes, "Flags"), it goes at the top of stdin above the data block; the notes decide.
- Nonce: `secrets.token_hex(8)`, retried up to 3 times on render_prompt's ValueError, then TriageFailed(refused_or_error).
- Seconds are measured with the injected monotonic clock around the process; cost and tokens come from the envelope fields the notes name, else None.

## E2E

`tests/test_triage_e2e.py` runs the real CLI as its own process (`run --dry-run`, and a live run with the fake Telegram transport) with a fake `claude` executable first on PATH: it covers the user-visible Claude line, the off path, a failing CLI and the cost file. The live call against the real Claude service is plan 04-01 (operator) and the enable step in plan 04-15's runbook.

## Failure behaviour

- `claude` subprocess: every failure class maps to one TriageFailed reason (list above); timeout kills the process group; no retry inside a run; the run's sends, exit code and state are unaffected (D-11).
- Temporary directory: created per call and removed in a finally block; a removal error is logged at WARNING with the error class.
- Cost file: live writes through FileTriageCostStore (plan 04-11 rules); dry-run writes nothing.
- Missing token with triage enabled: not_logged_in per call, logged; `doctor` reports it (plan 04-15). Not a config error, so the alerts still go out.
