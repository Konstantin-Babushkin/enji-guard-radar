## Decisions recorded here

- SRC-04 clarification (REQUIREMENTS.md, 2026-11-16): a well-formed answer with zero items is a real answer. `{"repositories": [], "has_more": false}` gives ProjectOk with zero repositories, and the stale rule calls that never ran. A blank, truncated or malformed response, a failed call or a page that was not fetched gives unknown and creates nothing. A listing with zero projects is a different case: there is no project to report on and it signals an outage, so it is ListingUnknown (exit 1) and touches nothing.
- Run paging bound: run pages are newest first by linked_at (OBSERVED), but completion order differs from link order. The reader keeps reading until has_more is false, or until the oldest linked_at read plus MAX_RUN_DURATION (24 h) is at or before the newest counting completion found. Error bound: exact whenever every run completes within 24 hours of being linked (OBSERVED: 5 minutes to about 2 hours). A longer run on an unread page can be missed, which makes the project look older than it is, never younger.
- STATE-01 in this plan: AlertKey is identity only, the generic (project, repo, audit type, level) key. `Alert.count` is an optional field (None for stale and never-ran) that plan 01-06 stores in state. The High-count semantics of STATE-01 (counts per repo and audit type, RULE-02/03, re-arm on a rise per STATE-07) are Phase 2 work.

GuardDataError(Exception). RunStatus StrEnum (completed, unknown) and ReportStatus StrEnum (ready, pending, unknown) are mapped from the raw string after strip() and casefold(); any other word becomes UNKNOWN, with the raw string kept in status_raw / report_status_raw (never dropped, never a crash).

Models: GuardProject(id, name); GuardRepository(id, project_id, name, provider, connected: bool); AuditRun(task_id, action_key, status: RunStatus, status_raw: str, report_status: ReportStatus, report_status_raw: str, created_at, linked_at, completed_at: AwareDatetime | None, task_available: bool | None = None), whose property counts is True only when status is COMPLETED, report_status is READY and completed_at is not None (SRC-03); RepoRuns(repository, runs: tuple[AuditRun, ...]); ProjectOk(project, repositories: tuple[RepoRuns, ...]), whose property newest_counting_run_at is the max completed_at over the counting runs of all repositories, or None; ProjectUnknown(project, reason: str); ListingOk(projects: tuple[GuardProject, ...]); ListingUnknown(reason: str). Aliases: ProjectData = ProjectOk | ProjectUnknown and ProjectListing = ListingOk | ListingUnknown.

parse_guard_time(value: str) -> datetime full-matches the pattern YYYY-MM-DDTHH:MM:SS, then an optional "." with 1 to 6 digits, then a mandatory Z or a +HH:MM / -HH:MM offset, then calls datetime.fromisoformat and astimezone(UTC). Anything else (naive, 7 digits, date only) raises GuardDataError. Page is a frozen generic dataclass (items: tuple[T, ...], has_more: bool, next_cursor: str | None). parse_projects_page, parse_repositories_page and parse_runs_page(payload: Mapping[str, object]) read the list keys projects, repositories and runs. A well-formed empty list is a valid page. A missing, null or non-list key, a missing or mistyped field, or a non-bool has_more raises GuardDataError. Unknown extra fields from Guard are ignored, because Guard may add fields.

list_projects(tools: GuardTools) -> ProjectListing pages with ARG_CURSOR until has_more is false. It returns ListingUnknown, with the reason logged at ERROR, on GuardCallError, GuardDataError, has_more true without next_cursor, more than MAX_PAGES pages, or zero projects in total.

fetch_project(tools, project: GuardProject) -> ProjectData pages TOOL_LIST_REPOSITORIES with {ARG_PROJECT_ID: project.id} plus the cursor. A well-formed empty repository list gives ProjectOk with zero repositories (SRC-04 clarification). Then, for every repository, it pages TOOL_LIST_AUDIT_RUNS with {ARG_REPOSITORY_ID: repository.id} plus the cursor, until has_more is false or the run-paging bound is met. After each page, take newest as the max completed_at of the counting runs read so far and oldest_linked as the min linked_at read so far; stop when newest is set and oldest_linked + MAX_RUN_DURATION <= newest. That is safe because runs are listed newest first by linked_at, so every unread run was linked no later than oldest_linked. When a page breaks that order (a linked_at later than one already read), log WARNING "run pages of %s are not newest first; reading all pages" and read to has_more false for that repository. Any failure, including a page call that fails after earlier pages succeeded, returns ProjectUnknown with a reason naming the tool, for example "list_repositories failed: simulated Guard outage", logged at WARNING; it is never a ProjectOk built from the pages read so far. The reader sends no limit argument and calls no other tool.

fixture_source.py: MANIFEST_FILE = "calls.json". FixtureCall(tool: str, args: dict[str, str] = {}, response: str | None = None, error: str | None = None, note: str | None = None) with a model validator requiring exactly one of response or error. FixtureManifest(calls: tuple[FixtureCall, ...]). FixtureGuardTools(directory: Path) loads and validates the manifest once; a missing or invalid manifest raises GuardCallError naming the file. call(tool, args) finds the entry whose tool equals tool and whose args equal dict(args) exactly. An error entry raises GuardCallError(error). A response entry is resolved relative to the directory, must be a relative path that stays inside it (absolute paths and ".." parts raise GuardCallError), is read with Path.read_text and json.loads, and must be a JSON object, else GuardCallError. No match raises GuardCallError("no recorded response for <tool>"). It only reads files: no network, no writes.

stale.py (RULE-01): StaleVerdict StrEnum (fresh, stale, never_ran, unknown). StaleResult(project_id, project_name, verdict, threshold_days: int, age_days: int | None, newest_run_at: AwareDatetime | None, repo_count: int, reason: str | None). STALE_SEVERITY = Severity.MEDIUM. evaluate_stale(data: ProjectData, threshold_days: int, now: datetime) -> StaleResult raises ValueError when now is naive. ProjectUnknown gives UNKNOWN with its reason. ProjectOk with newest_counting_run_at None gives NEVER_RAN with repo_count. messages.py: TELEGRAM_MAX_CHARS = 4096. escape(text) = html.escape(text, quote=False), the single escaping point for dynamic text. render_alert(alert) -> str builds three lines joined by "\n". For STALE: "Stale Guard scans: <b>{escaped name}</b>", then "No completed Guard run for {age} (last: {YYYY-MM-DD of last_run_at in UTC}).", then "Severity: {severity value}.", where age is "1 day" or "{n} days". For NEVER_RAN: "No Guard runs: <b>{escaped name}</b>", then "It has no repositories in Guard." when repo_count is 0, "No completed Guard run found in its 1 repository." when 1, else "No completed Guard run found in its {n} repositories.", then the severity line. render_messages(alerts: Sequence[Alert]) -> list[OutboundMessage] sorts worst first (SEVERITY_ORDER, then age_days descending with None last, then project name casefolded, then key.as_text()) and returns one message per alert with keys=(alert.key,). pipeline.py: Deps frozen dataclass (guard: GuardTools, notifier: Notifier, config: RadarConfig, clock: Clock). ProjectStatus StrEnum (evaluated, unknown). ProjectResult(project_id, project_name, status, stale: StaleResult | None, note: str). RunOutcome StrEnum (completed, attention, guard_unavailable) and EXIT_CODES = {completed: 0, attention: 1, guard_unavailable: 1}. RunReport(now, outcome, results: tuple[ProjectResult, ...], messages: tuple[OutboundMessage, ...], delivered: int, printed: int, not_delivered: int) with property exit_code.

run_once(deps) -> RunReport:
- now = deps.clock(), then list_projects. ListingUnknown gives outcome guard_unavailable with no results.
- Otherwise, for each project sorted by (name casefolded, id): fetch_project, then evaluate_stale with deps.config.thresholds_for(project.id).stale_after_days and now, then a ProjectResult with status evaluated (note "") or unknown (note "Guard data unavailable ({reason})").
- Render the non-None alert_for results with render_messages and send each message through deps.notifier. Count Delivered and Printed. On NotDelivered, log WARNING with error and detail, log ERROR with operator_action when present, and stop the loop when stop_sending.
- The outcome is attention when any NotDelivered occurred, else completed. Log one INFO summary line with the counts.
