<objective>
Build the radar's memory: a pure ledger that decides what is new, already alerted, retried, baselined or resolved (STATE-01, STATE-04, STATE-05, SRC-04 freeze), and a file store that writes it atomically with a backup, refuses to start from a corrupt file, and lets only one run hold it at a time (STATE-03, STATE-06). Purpose: double or lost alerts and a silent "state reset equals first run" flood are the riskiest failures for an executive audience (PITFALLS 3, 20, 21 and 22).

## Decisions recorded here

- STATE-01 split (decided 2026-11-16: High counts per (repo, audit type), dedup key (repo, audit type, level)). This plan delivers the Phase 1 part: the generic identity-only key AlertKey(project_id, repo_id, action_key, level), the never-re-send-an-alerted-condition rule, and an optional ConditionRecord.count in schema 1, so the on-disk format already holds a per-key count. It does not deliver the High-count semantics. Producing High-count conditions per (repo, audit type) (RULE-02, RULE-03), re-arming on a rise (STATE-07) and the debounced clear (RULE-09) are Phase 2 work, and none of that behaviour is built here.
- First-run baseline (ROADMAP question for the Phase 1 planner): a project's conditions on its first evaluation are recorded with baseline true and never sent. A project already stale on the radar's first run therefore stays silent until the Phase 3 digest, consistent with STATE-05 and with ALERT-01's "newly stale". The baseline is visible: plan 01-07 prints it in the dry-run and logs it. Reversible: one branch in `reconcile`. Operator confirmation is still requested (STATE.md blocker).
- Delivery policy: at-least-once. alerted_at is written only after an acknowledged send, so a crash between the acknowledgement and the save re-sends once (documented duplicate window, ARCHITECTURE.md "Crash and Replay Safety").
- Corrupt state halts and never auto-restores. The backup exists for the operator to restore by hand (STATE-03, success criterion 4: "a corrupt state file halts the run ... and nothing is reset").
