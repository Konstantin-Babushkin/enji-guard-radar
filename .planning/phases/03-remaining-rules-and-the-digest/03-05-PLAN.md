## Notes

- Sort of `low`: oldest run date first, then lower score, then project name casefolded, then repository id and audit type. The digest (plan 03-08) relies on that being deterministic, not on its meaning.
- The score is read from the newest completed run of each type even when that run has no High findings; reading it is plan 03-09's job (the skip rule), this plan only folds what the reader returned.
- "Unknown" has two shapes, both left unchanged here: the report is a `ReportUnknown` (counted in `unknown_reports`), or it has no entry because the skip rule did not read it (counted nowhere, the stored record is still the answer).
