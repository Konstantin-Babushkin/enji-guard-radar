## Notes

- Which data the digest reads: open High series and stale or never-ran projects come from the alerts that this run's evaluated projects produced (`ProjectEvaluation.alerts`), low scores and tooling gaps from `RunReport.low_scores` and `tooling_gaps`, resolved items from `state.resolved`, names from the run's project results. Paused and excluded projects produce none of them (SRC-05, D-10); a project that could not be read this poll produces none and is counted as unread.
- Interpretation recorded for the operator: a partially failed poll still sends the digest (some projects unread, said in its text); only a failed poll (listing unknown, or every active project unknown) defers it. Deferring on any single unreadable project would let one broken repository silence the heartbeat for good, against DIG-02.
- Window and timer: the first timer run at or after the planned moment sends; with the shipped 3-hour timer and the default 05:00 UTC that is the 06:00 UTC run. A window shorter than the timer tick can skip the week silently; `doctor` warns about it (plan 03-07).
- A multi-message digest (safety-net splitting) is marked only when every message was acknowledged; if the second of two messages fails, the whole digest is sent again on the next run in the window, so the first part can repeat. That is accepted (D-06 makes one message the normal case).
- Preview and test-chat steps for the operator are documented, not automated (no network, no credentials in this environment).
